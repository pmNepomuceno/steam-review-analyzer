# Decisions

Extends the decisions log in `PROJECT_BRIEF.md` section 10.

| Date | Decision | Reason |
|---|---|---|
| 2026-09-24 | Dev Postgres runs in Docker Compose on host port 5433 | Port 5432 is commonly taken by other local Postgres containers |
| 2026-09-24 | Backend pinned to Python 3.12 (uv venv, `python:3.12-slim` image) | System Python is 3.14, and ML wheels needed in M2-M3 may not support it yet |
| 2026-09-24 | Minimum 200 usable English reviews before serving a game (`MIN_REVIEW_COUNT`) | Enough for meaningful per-aspect breakdowns without excluding most indie games. A game that fails the guard is not marked ingested, so it can succeed on a later request |
| 2026-09-24 | Cap ingestion at 1000 reviews per game (`MAX_REVIEWS`) | Bounds first-request latency (about 10s for 1000 reviews) |
| 2026-09-24 | Serialize concurrent first requests with `pg_advisory_xact_lock(1, appid)` | Prevents duplicate Steam fetches without adding a job queue |
| 2026-09-24 | Ingest inside the request (blocking first call), no background jobs | Brief scopes v1 to fetch-and-cache; revisit if latency hurts the dashboard |
| 2026-09-24 | Added Starfield, Cities: Skylines II and PAYDAY 3 (Mixed ratings) to the dev data alongside Portal 2 and Hades | Portal 2 + Hades had only 47 negatives in 2000 reviews, too few to train or evaluate the minority class; the five games give 1097 negatives in 5000 |
| 2026-09-24 | Sentiment model trains on all cached games pooled, with `class_weight="balanced"` | One model serves any appid; balancing stops LogReg from winning by predicting "positive" everywhere |
| 2026-09-24 | Vectorizer + classifier saved as one sklearn `Pipeline` in `models_store/sentiment.joblib` | One artifact can't drift out of sync between vectorizer and model |
| 2026-09-24 | `ml/sentiment.py` loads the artifact lazily on first `predict()` and caches it; the API should call `load_model()` in its lifespan once M5 uses it | Importing the module must not fail on a fresh clone or in tests, where no trained artifact exists |
| 2026-09-24 | Sentiment eval is judged on minority-class (negative) F1 vs. a majority-class baseline, with per-game breakdown | Steam reviews skew positive, so accuracy alone rewards a do-nothing model. First run: negative F1 0.718 vs. baseline 0.000; accuracy 0.860 vs. 0.781. On the ~98%-positive games (Hades, Portal 2) model accuracy is *below* the baseline's |
| 2026-09-24 | Ingestion fetches the most recent reviews (`filter=recent`), up to `MAX_REVIEWS`, and never refreshes a cached game. Chosen during M1 but not logged until now | Simplest cursor walk. Consequence: all sentiment/aspect results describe *recent* opinion, not all-time. With the 1000 cap the cached window is only ~1-3 months per game (e.g. Portal 2: 2026-08-25 to 2026-09-24), which also limits the M6 sentiment-trend chart. Revisit before M6 (see brief section 9) |
| 2026-09-24 | Aspect embeddings use `sentence-transformers/all-MiniLM-L6-v2` on CPU | 22M params / ~90 MB, fast enough on a free-tier CPU; L3 variants lose too much similarity quality, bge-small/mpnet are 1.5-5x slower. Measured: ~1000 reviews (2-9k sentences) in 19-41s on a dev laptop CPU |
| 2026-09-24 | torch installed from the PyTorch CPU wheel index (`--extra-index-url` in `requirements/base.txt`) | The default Linux wheel pulls ~2 GB of CUDA libraries the deployment can never use |
| 2026-09-24 | M3 exposes `ml.aspects.assign_aspects()` as a standalone function; nothing is written to `review_aspects` yet, and the table/migration are deferred to M5 | M4 will retune anchors and threshold, which would make stored rows stale; and tagging 1000 reviews takes 20-40s, too slow to add inside the blocking first-request ingestion. M5 should persist via a batch pass over cached reviews, not inside `ensure_ingested` |
| 2026-09-24 | Model + anchor embeddings load once per process on first use (`aspects.load()` for eager warm-up), not at import | Same reasoning as the sentiment model: importing must stay cheap and offline-safe. Anchors are still embedded once, never per request |
| 2026-09-24 | Aspect score = max cosine over that aspect's anchors; the best aspect wins with no margin rule; exact ties go to the aspect listed first in `ANCHORS`; below `SIMILARITY_THRESHOLD` the label is `none` but the best score is still returned | Simple and deterministic. Sentences that fit two aspects ("the performance issues aren't worth the price") get whichever scores higher; M4 decides whether an ambiguity margin is needed |
| 2026-09-24 | Rule-based splitting also cuts clauses at `but/however/although/though/whereas/and` (fragments under 3 content words are merged back) and windows segments over 60 words; any unit still over the encoder's token limit is cut at token boundaries | Reviews often skip punctuation ("story is great but it crashes and the price is too high"), so sentence splitting alone would tag the whole thing with one aspect. Word windows keep run-ons sentence-sized; the token cut is what actually stops the encoder silently truncating (a word count can't bound CJK or long URLs). BBCode stripping only matches known Steam tag names so bracketed prose survives, and common abbreviations (e.g., vs., Mr.) don't end sentences |
| 2026-09-24 | Initial `SIMILARITY_THRESHOLD = 0.40` | On 26 hand-picked sentences, clear off-topic ones scored <= 0.378 ("great game") and clear aspect ones >= 0.405. The gap is thin, and the set partly shaped the anchors (e.g. network-disconnect and quest-bug anchors were added after misses), so it is optimistic. Over all 5 cached games, 69-84% of sentences land in `none`; the 0.33-0.47 band is noisy in both directions (e.g. "The heists are fun & engaging" 0.387 -> none; "I hated it." 0.444 -> story; the quest-bug anchor pulls quest-content sentences into bugs). Anchors avoid generic words like "game"/"buy", which earlier pulled "great game" to price at 0.54. Real precision/recall comes from M4 |
| 2026-09-24 | M4 eval sample: 140 sentence units, 28 per game regardless of game size; per game 7 just below and 7 just above the threshold (±0.10 band), 4 long units (≥ 25 words, outside the band), 10 clear cases round-robin over every predicted class incl. `none`. Deduplicated on normalized text, seed 42 (`scripts/build_eval_sample.py`) | Pure random sampling would be ~75% easy `none`s and would miss the two known M3 failure modes (the noisy 0.33-0.47 band and glued-clause dilution). Because the band is oversampled, per-class numbers describe a deliberately hard sample, not the population; the meta file keeps population counts per stratum so the report can show the difference |
| 2026-09-24 | Gold labels are hand-labeled blind: `docs/eval/aspect_labels.csv` has no prediction columns, and the model's side lives in `aspect_sample_key.csv`, joined on id | Seeing the prediction biases the labeler toward agreeing with it, which inflates precision |
| 2026-09-24 | Labeling rules (`docs/eval/ASPECT_LABELING.md`): label topic not sentiment; primary clause wins; for equal-weight clauses the first-mentioned aspect wins and the row is flagged `ambiguous=y`; graphics/audio/art are `none` with a topic tag in `notes` | Makes ambiguous cases ("worth every penny, been playing for 200 hours") decided by a written rule, not ad hoc. The ambiguous flag lets the eval report metrics with and without them, and the notes tags measure whether a missing aspect (e.g. graphics) is a real gap |
| 2026-09-24 | `ml.aspects` now exposes per-aspect scores (`score_aspects`, `score_units`) and a single `label()` rule used by `assign_aspects` | The eval needs the runner-up aspect and must re-label at other thresholds and with edited anchors without duplicating the argmax/threshold logic |
| 2026-09-24 | `build_eval_sample.py` records the sha256 of the labels file it writes in `aspect_sample_meta.json` and refuses to rebuild once the file no longer matches; `--force` copies the labels, key and meta files to `*.bak-<UTC time>` first. All three files are written to `*.tmp` and renamed into place only after every write succeeds | A content check ("is any gold_aspect filled?") missed labels saved with `;` delimiters (Excel in pt-BR/European locales) or renamed columns and would have silently blanked them. The temp-then-rename step stops a mid-write failure from leaving a new labels file next to an old key |
| 2026-09-24 | Key-file scores, similarity and margin are written at full precision (`repr`), not 4 decimals | `evaluate_aspects.py` re-labels from the key at other thresholds; rounding moved scores across the cutoff (0.39996 -> 0.4000 re-labels `none` as an aspect). The sample was regenerated with the same seed: same 140 units, byte-identical labels file |
| 2026-09-24 | `aspects.load()` rejects an `ANCHORS` entry with no phrases | Score columns follow `ANCHORS` order only while every aspect has an anchor; an emptied list would shift every later column onto the wrong aspect name in `label()` with no error |
| 2026-09-24 | `evaluate_aspects.py` re-scores the key's sentences with the current `ANCHORS` by default; `--from-key` uses the scores stored when the sample was drawn | Anchor tuning becomes edit-then-rerun with no rebuild of the sample, and the gold labels stay valid because they describe the sentence, not the model. The report says whether anchors changed since sampling and how many predictions moved |
| 2026-09-24 | Aspect eval reports accuracy with a 95% Wilson interval and per-class P/R/F1 next to a majority-class baseline, for all rows, for unambiguous rows only, and population-weighted (each unit weighted by its game+stratum population count / sample count). Macro F1 averages only the classes that appear in the gold labels | With 140 units a single number hides a wide interval. The sample deliberately oversamples the hard band, so the unweighted numbers understate real-world accuracy; the weighted ones estimate it. The baseline shows how much of the accuracy comes from `none` being common |
| 2026-09-24 | The eval report includes a threshold sweep (0.30-0.50) over the same scores, marked as tuning on the eval set | Picking `SIMILARITY_THRESHOLD` needs the trade-off visible, but there is no separate held-out set, so whatever value is chosen from the sweep gives optimistic numbers and must be quoted that way |
